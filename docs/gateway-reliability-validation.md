# 基站可靠收发与 MMS 验证

本轮修复对应设备协议 v2 与基站端 1.1.3。客服端支持五个独立安装身份，并以 `MM-dd HH:mm:ss` 显示聊天时间；监视端同步显示时间和图片。

## 功能与部署

- 手机持久保存待收短信、彩信、派发记录和状态回执；断网恢复后自动继续处理。
- 普通出站任务先持久接收再 ACK，已接受任务不会因租约到期重新下发；旧 v1 设备和短信检测继续兼容。
- SIM 号码同步以原设备和卡槽更新，保留 SIM ID、地区、备注、账号绑定和聊天归属。未知或不完整号码不会覆盖后台号码。
- MMS 接受结构合法的 GIF，并保留 JPEG/PNG/AMR；上传失败可使用原消息身份重试。
- 管理面板支持修改地区名称，关联字段在事务内同步；原手机号与账号绑定保留。

协议、增量部署及回滚边界见 [reliable-message-delivery.md](reliable-message-delivery.md) 和 [device-phone-number-sync.md](device-phone-number-sync.md)。已有生产库只补缺失的 `007_message_delivery.sql`；不要重放初始化脚本，不要把历史 Processed/Sent/Delivered/UNKNOWN 消息改回 Pending。

基站仍以 base64 提交图片，服务器保存到私有对象存储，客服在会话鉴权后取得限时签名 URL。内网上传与公网下载可分别配置 `s3_endpoint_url` 和 `s3_download_endpoint_url`。通过 Cloudflare Tunnel 提供下载域名时，应将该域名路由到 S3 API，保留签名的 Host，并对该域名绕过 CDN 缓存。不要开放存储控制台或把私有桶改为公开。

运行配置、存储凭据、签名私钥、设备备份、聊天内容及 APK 不纳入源码提交。对象存储数据盘迁移必须先备份，验证字节一致后切换挂载，并保留可恢复副本。

## 验证结果

2026-10-09 的单台实际手机试点覆盖：普通回复、长短信、定时短信、断网期间排队发送、两条相同文字分别收信、GIF/JPEG 彩信入库、原客服账号读取、监视端接口及公网签名图片下载。用户随后确认客服端能够收到并查看图片。

- 四条试点出站测试均收到 Delivered 回执，各只有一次派发和一条手机发送记录。
- IP 网络断开期间收到的两条相同文字联网后分别入库；没有误合并。
- 新旧 11 个附件下载均成功且字节校验一致；无签名、篡改或过期签名均拒绝访问。
- 原消息、附件、设备/SIM 身份、客服账号绑定和会话路由均核对保留；旧 Processed 未重新派发。
- 连续锁屏观察约 10 分钟，进程、前台服务和心跳正常，断网恢复无需手动上线。
- 基站 JVM 测试 130 项通过；服务器 568 项通过。默认跳过的对象存储集成项已用独立 PG 和真实 PNG/GIF 对象另行验证；监视端 399 项通过。

实测普通短信创建至 Delivered 回执约 1.1 秒，长短信约 1.9 秒；新 JPEG 从手机接收记录到服务器入库约 7.9 秒，公网图片下载约 0.1–0.2 秒。这些是少量试点样本，不是延迟上限或服务承诺。隔离环境的 15 客户端并发测试无重复派发，模拟创建至客服读取 Delivered 的 p95 约 1.63 秒，不含真实运营商、外网和手机界面渲染。

## 保留的行为和验证边界

定时短信本次晚于设定时间约 27 秒，没有提前发送；到期任务仍受约 60 秒驻留轮询兜底的影响，不保证秒级准点。

现有入信逻辑会将全局联系人的地区更新成接收 SIM 的地区。跨地区来信可能改变这个联系人字段；手机号自身地区、账号绑定和原会话地区/路由不变。此次未修改该既有规则，不能将数据核对描述成每个联系人地区完全不变。

单台约 10 分钟观察不能替代长时间或全设备验收。其余手机须使用各自原签名覆盖升级，只安装基站端；不卸载、不清空应用数据，不以服务端心跳代替 APK 版本核对。

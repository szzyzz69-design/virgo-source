# MMS 接收版本上线与验收

更新时间：2026-10-06。

本次实现范围：接收已由默认短信应用下载的传统 MMS，保留正文与附件，由客服查看。基站权限及附件可读性已由用户真机验证。未加入 MMS 发送或 RCS。

## 已实现

- 服务端新增 `POST /mobile/v1/inbox/mms`，使用注册设备 token。设备 ID 由认证结果确定，请求体不能指定其他设备。
- 请求结构沿用 `MmsDownloadedPayload`：messageId、sender、recipient、simNumber、body、subject、receivedAt、attachments；附件包含 partId/contentType/name/size/data。空正文和无附件的纯文本 MMS 均允许，声明附件却没有 data 时拒绝。
- 上传完整内容后复用现有 MmsWebhookService 入库、存储附件、分配会话、通知客服。首次返回 201；同 ID/同内容重试返回 200、`created=false`；同 ID 不同内容返回 409。
- JPEG、PNG、AMR、octet-stream 继续使用已有白名单。单附件 10 MiB、附件总量 20 MiB，新接口 JSON 请求体最大 29 MiB。
- 基站不再把图文 MMS 转为 SMS，也不再把通知头和下载完成分别向业务服务器上报。MMS 统一走新设备认证入口；SMS 上报保持原流程。
- 上传前先在应用私有 `noBackupFilesDir/mms-outbox` 落盘，文件内容不可变。WorkManager 只调度任务，不通过 inputData 携带 Base64。2xx 后写入完成标记，断网/响应丢失可以安全重试。
- 读取失败保留待重扫状态；按每条 provider ID 检查两次稳定内容，不再以递增高水位跳过较早 ID。运行时扫描，启动补扫，另有 WorkManager 周期补扫；系统调度和省电策略仍可能推迟执行。
- 每个上传任务绑定原服务器地址和设备 ID，不能因换账号/服务器而用新身份上传旧任务。
- 独立客服端新增嵌套附件解析、图片气泡、预览、加载失败重试和有界图片解码；SSE 后刷新会话，同 ID 更新不重复加未读。
- 有既有 CDN URL 的附件继续使用原地址；URL 为空的私有对象在客服通过会话权限校验后生成 15 分钟有效下载链接。过期后重新打开会话即可取得新链接。

## 上线顺序

1. **先更新服务端**。已有数据库若包含 `messages.message_type=MMS` 和 `message_attachments`，本次不需要额外数据库迁移。较旧数据库应先补齐仓库原有 MMS 表结构，不能只重启 Docker 就假定初始化 SQL 会再次执行。
2. 配置可用的 S3 endpoint、region、bucket 和读写凭据。未配置 CDN 时，签名 URL 的 endpoint 必须能从客服手机访问，不能只使用服务器内部 DNS/localhost。生产请求继续使用 HTTPS。
3. **更新基站端**，保留原有注册信息和服务器地址。默认短信应用继续负责下载 MMS，确认基站云服务启用、SIM 已注册。新入口不需要额外 webhook 签名密钥。
4. **更新实际发布的客服端**。独立 `G:/project/virgo_kf` 已补齐图片能力；`G:/project/virgoPhone/virgo_kf` 保留其已有图片实现，修正了纯文本 MMS 错显下载中的行为。不要混淆两份源码的其他功能差异。
5. 已有待发送的老 MMS webhook 队列需要在切换前查看；新代码不再产生 MMS 通知头 webhook，但旧队列不会自动删除。旧通知占位记录不会自动与新消息合并。

## 首次补扫与故障恢复

- 新扫描策略首次启用时记录“当时往前 24 小时”的固定边界；之后不会随时间向前移动，所以停机期间较早的 MMS 仍可在重启后补扫。早于初始边界的记录需要通过已有历史导入流程处理。
- 过去曾被旧版本转成 SMS 的图文彩信，补扫后可能另生成正确的 MMS 记录。新旧协议 ID 不同，不自动删除或合并旧短信。
- 网络、408、429、5xx 保留原始请求并退避重试。其他 4xx 进入失败状态，内容保留在本地，基站日志显示任务 ID 和 HTTP 状态。
- 修复服务端版本、鉴权或格式问题后，停止并重新启动基站接收服务，会重新尝试保留的失败任务。409 内容冲突、413 超限、415 不支持类型需要解决对应原因；仅重启不能消除它们。
- 停止接收服务会取消本次新增的扫描和上传任务，但保留本地内容；重启后继续处理。清除应用数据或卸载会删除本地队列，不能用于普通重试。
- SIM 无法确定或附件尚不可读时不上传不完整消息，日志记录原因并等待重扫。

## 验收步骤

1. 客户端分别发送纯图片、图片加中文说明、两张图片和纯文本 MMS；确认消息详情显示 MMS，而非 RCS。
2. 检查基站日志出现 `MMS uploaded`，服务器会话出现一条 MMS，客服图片可以打开。
3. 关闭基站互联网后接收并下载一条 MMS，恢复网络后应自动上报；Google Messages 下载本身需要可用的运营商 MMS 通路。
4. 在消息已落本地队列后重启基站应用，确认继续上传且服务器不重复生成记录。
5. 延迟下载较早的一条彩信，在较新彩信已处理后再下载较早记录，确认仍可接收。
6. 双 SIM 分别接收，核对服务号码及客服归属。
7. 客服停留在会话时接收新图，确认自动刷新、图片可见且未读不重复累加。
